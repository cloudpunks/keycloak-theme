# Theme — Agent Guide

This document provides guidance for AI coding agents (GitHub Copilot, Codex,
Claude, Gemini, etc.) working in this repository.

## Overview

This repository defines Cloudpunks' customized Keycloak theme (login, account
and email), built with [Keycloakify](https://www.keycloakify.dev/), **React**,
**TypeScript** and **Vite** on top of the
[shadcn Keycloakify theme](https://github.com/OussemaSahbeni/keycloakify-login-shadcn).
`keycloakify build` internally generates a Maven project and shells out to
`mvn` to package the compiled frontend into a Keycloak SPI provider **JAR**.
That JAR is then repackaged as a single-layer OCI artifact and pushed to
`ghcr.io/cloudpunks/keycloak-theme` via GitHub Actions on pushes to `master`
and on version tags — there is no Dockerfile/Buildah build involved. The
image is designed to be mounted straight into the Keycloak pod's
`providers/` directory via a Kubernetes
[image volume](https://kubernetes.io/docs/tasks/configure-pod-container/image-volumes/)
(`.spec.volumes[].image`), so there is no runnable base image — just the
JAR's content.

## Tooling & Environment

The development environment is managed with [mise](https://mise.jdx.dev/).
Tool versions are pinned in `mise.toml`:

- **Node.js** — build and test runtime
- **Java / Maven** — needed by `keycloakify build`'s internal `mvn` invocation
- **oras** — available for manual/local OCI pushes; CI itself pushes via the
  `1k-off/action-oras-push` GitHub Action, so it doesn't need `oras` on the runner
- **prek** — Git hook runner (Rust reimplementation of pre-commit), driven by
  `.pre-commit-config.yaml`
- **betterleaks** — secret-leak scanner, run as a pre-commit hook

To install the pinned tools and activate the environment:

```console
mise trust
mise install
```

Install JavaScript dependencies with:

```console
npm install
```

## Pre-commit Hooks

Hooks run automatically via `prek` (installed through `mise`, a Rust
reimplementation of pre-commit that reads the same `.pre-commit-config.yaml`):

- `commitlint` (commit-msg stage) — lints commit messages against Conventional
  Commits, using the custom type list in `commitlint.config.cjs`
- `betterleaks` (pre-commit stage) — scans staged changes for leaked secrets

Run them manually:

```console
prek run --all-files
```

Set up the git hook types once per clone:

```console
prek install --hook-type pre-commit --hook-type commit-msg
```

## CI/CD Pipeline (GitHub Actions)

All workflows live in `.github/workflows/` and use `jdx/mise-action` to
install the exact tool versions pinned in `mise.toml` — no manual `PATH`
plumbing needed.

- **`general.yml`** (job `testing`) — on every push/PR to `master`: `npm ci`,
  `npm run lint`, `npm run build-keycloak`. Validates that the theme still
  type-checks, lints and packages into a JAR.
- **`image.yml`** (job `image`) — on push to `master` and on version tags
  (`v*`): builds the theme, renames the produced JAR to a fixed
  `keycloak-theme.jar`, computes a tag (`latest` on `master`, or the tag name
  with its leading `v` stripped on a version tag), and pushes it as an OCI
  artifact to `ghcr.io/cloudpunks/keycloak-theme` via the
  `1k-off/action-oras-push` action.
- **`storybook.yml`** (job `storybook`) — on push/PR to `master`: builds
  Storybook and deploys it to GitHub Pages.
- **`release.yml`** (job `release`) — scheduled weekly (Mondays, 08:00 UTC)
  plus manual dispatch: runs `semantic-release` (per `.releaserc`) using a
  short-lived GitHub App token, producing tags/changelog/GitHub releases.
- **`automerge.yml`** (job `dependabot`) — on PR events from `dependabot[bot]`:
  auto-approves and enables auto-merge.

Branch protection on `master` is defined in `.github/settings.yml`
(required status checks, PR-only merges, linear history) and applied by a
GitHub settings app/bot, not by a workflow in this repo.

## Deploying the theme

Every push to `master` or a version tag (`vX.Y.Z`) automatically builds the
theme and publishes it as a minimal single-layer OCI image to
`ghcr.io/cloudpunks/keycloak-theme:latest` (or `:X.Y.Z`) via the `image`
GitHub Actions workflow — no manual step is required. On the Kubernetes side,
mount it directly into Keycloak's `providers/` directory with an image
volume, e.g.:

```yaml
volumes:
  - name: theme
    image:
      reference: ghcr.io/cloudpunks/keycloak-theme:latest
      pullPolicy: Always
containers:
  - name: keycloak
    volumeMounts:
      - name: theme
        mountPath: /opt/keycloak/providers
        readOnly: true
```

## Conventions

- Follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)
  for all commit messages (enforced by the `commitlint` pre-commit hook and
  the `semantic.yml`-based PR title check); the accepted type list is
  customized in `commitlint.config.cjs` (adds `major`/`minor`/`patch`/`deps`
  on top of the standard types, feeding explicit version-bump rules in
  `.releaserc`)
- All changes must go through pull requests; branch protection on `master`
  requires passing status checks and blocks force-pushes/direct deletion
- Use `feat/`, `fix/`, `chore/` branch prefixes
- Releases follow [Semantic Versioning](https://semver.org/), cut by the
  scheduled `release.yml` workflow
- Do not manually edit `src/kc.gen.tsx` — it is regenerated by the
  Keycloakify `update-kc-gen` command
- Prefer the existing `components/ui` (shadcn/ui) primitives over introducing
  new UI libraries
- Dependency updates: `renovate.json` extends the shared `cloudpunks/.github`
  preset via the Renovate GitHub App, with a repo-local `minimumReleaseAge`
  override (avoids proposing a version before Renovate's own package mirror
  has caught up with a very recent publish). `automerge.yml` is also set up
  to auto-approve/auto-merge Dependabot PRs, but no `.github/dependabot.yml`
  exists yet, so Dependabot isn't actually opening PRs here — only Renovate is.
